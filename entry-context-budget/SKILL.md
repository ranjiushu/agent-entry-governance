# Agent 入口文档治理：把入口文档写成项目／工作区的「简历」

入口文档是项目／工作区的「简历」：写给陌生人看，Agent 通常是它的第一读者。目标是简洁、美观、优雅——几分钟看明白这是哪儿、有什么规矩、细节去哪儿找；同时不许长到挤爆默认上下文。手段：体积预算、信息密度、事实归属。这套判据的理据收在 references/philosophy.md，按需加载；本文只留判据与动作。

第一原则：入口文档不是知识库，它是简历，也是人与 Agent 共用的上下文入口——而 Agent 的默认上下文是稀缺资源。

管什么：入口文档与它指向的下游文档的关系，不让它膨胀、腐烂成过时副本、出现第二处事实源。不管什么：整个仓库的通用文档生命周期。命名、层数、拆分形态由环境声明：脚本默认发现 AGENTS.md / AGENT.md，别的命名用 --names 注入。

文档分三层：策略（要什么，稳定）、机制（怎么强制，可替换）、实例（具体值，外置）。判准：一句话里若含只有本环境才成立的专名、数值或形态，它就不属于策略层。

## 〇、判准的立足点：以人为本

入口文档没有客观最优解，与其争论「多大最合适」，不如取一个能复核的标准：好看、易看、愿意看（读得下去、不被形式劝退，不是要写得动人）。人读得进去，才愿意改、愿意用、愿意把判断放进来，所以体积阈值只管有没有失控，判决权在人的阅读体验。默认读者是不熟悉这个项目的人，不是作者本人。完整论证见 references/philosophy.md。

操作上三条。判据用 token（机器能强制的只有体积代理），但终审要看**实排的页面**，像读者那样通读一遍，不只看一个数字。排版是可用的杠杆：真表格、留白、标题层级、长短句都为「愿意看」服务，值得为它们花掉一些页数。**渲染可用而不跑页面，终审不算完成；渲染不可用时，交付须显式标注「未经页面终审」。**

三条边界常驻，不随「好看」让步。**安全与不可逆约束**（敏感资产、关键路径、fail-closed 关口）照原样写死。**精度**不牺牲：事实、路径、命令、判断照准写，不为了顺口变模糊——文档的可信度就是它的功能。**上下文**不破坏：超限走下沉（把细节搬走），不走删真相。

「简历」这个比方可以直接判决一段话的去留：读者是陌生人；放「从哪来、现在怎样」，不放生平流水账；不能撒谎，不该过期。它只借结构不借说服——不必打动谁，服务的是人际协同：让人知道从哪儿开始对话、该问什么。调性是交接说明，不是宣传文案，也不是流水账。

### 与 README 的分工

简历管「简」与「历」：一眼看懂这是哪儿、要守什么，加上来历与现状。README 讲项目本身：在干什么、要去哪、影响上手的技术细节；它是项目自己的声音，换个负责人换调性，不必求统一。

判据不在内容类别，在**代价结构与触发时机**：入口文档被注入，每次开工都占一份上下文，只放「不知道就会做错」和「马上要用的入口」；README 被取用，代价只在被读时发生，放想了解才需要的东西。

三个测试判一条内容该放哪。**注射测试**——每次会话都必须读到吗？是，进简历。**违反测试**——不知道就会做错吗？会，简历里至少留一句加指针，细则仍可放 README。**删除测试**——删了会立刻坏吗？会坏，进简历。推论：同一事实只写一处，一处写、一处指；简历过期直接导致错误动作，README 过期只是误解，所以简历宁短勿滥，README 宁可写全。

## 何时使用

加内容之前先量，越线先精简；要装关口、要拆分、要把策略搬到别处（§七）时也用。

## 一、核心思想（比脚本更重要）

1. 门禁是一个必被执行的关口。skill 无执行保证（框架没加载、没被选中、人可绕过），不能充当门禁；关口的选法见 §四。
2. 判据用 token 不用字节（字节对中文失真约 3 倍）。体积只是可强制的代理，目标是信息不重复、可导航；越线是信号，不是结论。
3. 上限的目的不是少写，是逼出指针化下沉：信息搬家，不删关键约束。搬之前先审接收方：目标须存在、可用、且尚未持有该事实。
4. 阈值是策略，只有一处。权威值只写在度量实现里，任何地方不抄第二份数字。
5. 量将要生效的版本：有版本控制就量暂存版，没有就量工作区。前提缺失显式响应，不静默换个对象来量。
6. 缺依赖要响，不能静默；哑门禁比没门禁更危险（清单见 §四.1）。
7. **长度不是目标函数，把故事讲清楚才是。** 第一次翻开它的 Agent 要能说出三件事：这是什么地方、为什么有这些规矩、细节去哪找——这三件事本身就是内容，不可指针化。砍重复、背景、可派生的事实，不砍因果与最短路径；一张每行都写着「→ 见某文件」的卡什么也没讲。页数陡增是信号，页数变小不是成绩。

## 二、度量与判据

度量器只读、永不阻断；判据给退出码，供关口 fail-closed 调用。精确用法以脚本自述为准，本文件不复述参数。

| 指标 | 阈值语义 | 处置 |
|---|---|---|
| token 近似 | 过提醒线 | 提醒 |
| token 近似 | 过上限 | 拒绝，先精简 |
| gzip 体积 | 过冗余线 | 告警，查重复或灌水 |

数值与适用范围以 --print-policy 及度量实现自述为准，勿抄；别在任何文档里记当前数值（漂移事实），要现状现场量。

### 人类刻度（判决依据）

人感觉不到 token，感觉到的是页面：度量并列给出实排页数，判据本身仍只用 token。实排含短行与行尾留白，与算术值实测可差近一倍，**差值即排版开销**（格式堆砌的量），换算绑定写死的排版标准。渲染器是外部依赖，不进判据、永不阻断；缺依赖时要显式说明「这次没看到页面」——终审缺了页面等于判决没有依据（§〇）。

## 三、超限了怎么办

先定去留，再动手：

| 判定 | 何时适用 | 动作 |
|---|---|---|
| Keep 留 | 几乎所有任务都需要，稳定，无法派生 | 留在入口 |
| Point 指 | 部分任务才需要，有明确归属 | 下沉加指针（下方 2） |
| Derive 派 | 可从代码、配置、探针派生 | 删静态副本（下方 1） |
| Delete 删 | 历史背景，已失效，无决策价值 | 删除或归档（下方 3） |

0. 先审接收方（§一.3）：目标可用吗？该事实已在别处有源吗？
1. 删可由代码或探针派生的事实（计数、比例、当前值），改成以探针为准。
2. 指针化下沉：细节、背景、踩坑史移到下游，原地只留一行指针加稳定短名。
3. 归档历史：过期计划、被取代方案移到归档区。
4. 职责切割：不同读者或用途分开，同一内容只许出现在一处。
5. 拆分：按内在关系切分，入口路径稳定，引用按名不按号。必须降低默认上下文成本——Agent 仍需同时读全部碎片则不算数。
6. 保因果（§一.7）：「为什么有这条规矩」和「最短怎么用」留在入口。判一条要不要留，问一句「读者不跳出去，能不能明白它」，不能就把理由一起留下。

合法的动作只有上面六种，且必须满足「信息搬家，约束不删；阈值变更需批准；关口必过；搬迁必治」。长度变短不是精简合格的证据，删了必要的话反而更糟。

## 四、把关卡装成必被执行的关口

机制层三角色：度量（只读）、判据（退出码）、安装器（幂等落地）。必须做到：

1. fail-closed：守卫缺失、解释器不可用、退出码意外，一律拦截并报错。
2. 薄壳加幂等：关口只在自己标记块里调用守卫，重跑不叠块；逻辑全在守卫里，多仓共用。
3. 量将生效版本（语义以判据脚本自述为准）：未纳入提交的显式跳过、未改动的存量豁免、前提缺失拒绝。
4. 装完实测拦截：越线被拦、合规能过、未改动能过，没实测不算装好。
5. 守卫本体随目标入库：只依赖技能目录会让 clone 的人静默失效。

选关口按「一定跑到」排序：有版本控制选提交点，其次流水线，再次启动入口或任意自动化；都没有就退化为入口提示，不假装已装。是否已装：跑校验，不背记忆。

## 五、给 AI agent 的行为规则

1. 改入口文档前后各量一次，越线先精简再提交。
2. 新增段落先估 token，估不准就量。格式符号也占 token：满屏加粗、反复强调，全是重点等于没有重点；先去味，再精简内容。
3. 提交前量将生效版本，别把随手看到的数当提交的数。
4. 阈值、判据、算法一律引用权威源，不生成第三份数字。
5. 精简或拆分后验指针可达、验无第二事实源、按名改引用、重建下游检索索引；并报账：搬走什么、搬去哪、入口现在如何找到它。
6. 交付前跑终审（§六），此时才读 references/final-audit.md。
7. 别把「变短」当成交付证据。精简后通读一遍，读者仍能说出这是什么地方、为什么有这些规矩、细节去哪找（§一.7）；不能，就是砍过头了。
8. 判决看页面（§〇）：渲染可用就跑渲染并通读实排结果；不可用就在交付里显式标注「未经页面终审」，别只读一个 token 数字就宣布合格。

## 六、交付前终审（渐进式披露反例）

反例不进生成阶段的上下文，只在终审时读 references/final-audit.md。
终审：再量一次（§二），清单逐条答是或否；有否就返工再审，全是才交付。

## 七、可移植性

可移植单元是本目录（SKILL.md 加 scripts/）。硬约束：纯标准库、不联网、度量与判据不写文件、不依赖版本控制（它只是取将生效版本的增强）。

| 环境 | 怎么用 |
|---|---|
| 支持 skills | 放进 skills 目录，读 SKILL.md |
| 不支持 skills | SKILL.md 正文进系统提示词；工具直接跑 |
| 有版本控制 | 守卫装到提交点 |
| 只有流水线或启动入口 | 在其中 fail-closed 调判据 |

## 八、权威来源与自身一致性

- 阈值与算法唯一事实源：度量实现（--print-policy）。
- 本技能自身也守这些不变式：无第二事实源、无漂移引用、描述与随附物一致（提到的产物必须真随附，否则不提）。

## 九、文风（正面标准）

密度治理回答「多不多」，文风回答「读不读得下去」。判据是「读起来像不像人写的」，四条方向——直陈、句子先于条目、节奏要变、具体胜于抽象——连同示例收在 references/style.md，写文档与终审时对照。
