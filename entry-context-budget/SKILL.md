# Agent 入口文档治理：把入口文档写成项目／工作区的「简历」

入口文档是项目／工作区的「简历」：写给不认识这里的人看，而 Agent 通常是它的第一读者。目标就是一份好简历该有的样子——简洁、美观、优雅，让人几分钟内看明白这是哪儿、有什么规矩、细节去哪儿找；同时不许长到挤爆 Agent 的默认上下文。手段还是老几样：体积预算、信息密度、事实归属。

第一原则：入口文档不是知识库，它是项目／工作区的简历，也是人与 Agent 共用的上下文入口——而 Agent 的默认上下文是稀缺资源。

治理时不许越两条线。**精度**——事实、路径、命令、判断不许为了顺口写模糊，文档的可信度就是它的功能。**上下文**——卡片不能长到挤爆默认上下文；超限走下沉（把细节搬走），不走删真相。

管什么：入口文档与它指向的下游文档的关系，不让它膨胀、腐烂成过时副本、出现第二处事实源。
不管什么：整个仓库的通用文档生命周期管理。
命名、层数、拆分形态由环境声明：脚本默认发现 AGENTS.md / AGENT.md，别的命名用 --names 注入。

文档分三层：策略（要什么，稳定）、机制（怎么强制，可替换）、实例（具体值，外置）。判准：一句话里若含只有本环境才成立的专名、数值或形态，它就不属于策略层。

## 〇、判准的立足点：以人为本

入口文档没有客观最优解，与其争论「多大最合适」，不如取一个能复核的标准：好看、易看、愿意看（这三条说的是读得下去、不被形式劝退，不是要写得动人）。前提是协作里人仍然主导——人读得进去，才愿意改、愿意用、愿意把自己的判断放进来，最终产出未必比「机器最优排版」差。所以体积阈值管的是有没有失控，不当目标；判决权在人的阅读体验。

操作上三条。判据仍旧用 token（机器能强制的只有体积代理），但终审要看**实排的页面**，像读者那样通读一遍，而不是只看一个数字。排版是可用的杠杆：真表格、留白、标题层级、长短句都为「愿意看」服务，值得为它们花掉一些页数。

三条不干扰的边界常驻，不随「好看」让步。安全与不可逆的约束（敏感资产、关键路径、fail-closed 关口）照原样写死。**精度**不牺牲：事实、路径、命令、判断照准写，不为了顺口变模糊——文档的可信度就是它的功能。**上下文**不破坏：卡片不能长到挤爆 Agent 的默认上下文，超限就走下沉（把细节搬走），不走删真相。

可读性不只是礼貌，它是**分发机制**。GUI 让个人电脑走出实验室，Python 让编程散到非科班的人手里——它们赢的不是性能，是「不看你简历也敢上手」。文档同理：写得像人能读的，才会被接手、被引用、被发现错误、被传下去；读不进去的只有作者自己看得懂，也就活不过作者离开。所以默认读者定为**不熟悉这个项目的人**，而不是作者本人。

反过来也要认：可读换不来内容。空壳再顺眼也走不出去，判准是把真东西讲得人能进，不是把页面弄漂亮。

「简历」这个比方可以直接拿去判决一段话的去留：读者设定是陌生人，不是作者也不是老同事；简历不放生平流水账，放的是「从哪来、现在怎样」；简历不能撒谎，也不该过期。落到文档上——判断所需的因果与最短路径留着，细节、背景、踩坑史交给附件（下游分册）；路径、命令、数值照准写；事实变了就改，别留一份过期的自述。

这个比方**只借结构，不借说服**：入口文档不做叙事层面的优化，不必打动谁，把故事讲清楚即可。它服务的是**人际协同**——像简历撮合求职者和招聘者坐下来谈一样，入口文档的作用是让接手的人（人，或作为第一读者的 Agent）知道该从哪儿开始对话、该问什么。职能决定调性：它是交接说明的口吻，不是宣传文案，也不是流水账；该省略的省略，详略取舍本身也在服务协同。

### 与 README 的分工：简历是「简」与「历」，README 讲项目本身

简历两件事。**简**——简洁明朗，一眼看懂这是哪儿、要守什么。**历**——来历与现状，它从哪来、现在处于什么状况。历是精选的轨迹，不是逐日生平；交代这些是为了让人知道现在该怎么配合它，不是为了说服谁。

README 回答三件事：这个项目到底在干什么、要到哪里去、以及一部分影响上手的具体技术细节。它比简历更像项目自己的声音——同一个项目的 README，换个负责人就会换调性与取舍，不必求统一。

两者同处一个目录时常重叠。判据不在内容类别——谁都能写规矩——而在**代价结构与触发时机**：

- 入口文档被**注入**：框架自动加载，每次开工都占一份上下文。所以只放「不知道就会做错」和「马上要用的入口」。
- README 被**取用**：人来了才翻开，代价只在被读时发生。放的是想了解才需要的东西。

三个测试，判一条内容该放哪：**注射测试**——每次会话都必须读到吗？是，进简历。**违反测试**——不知道就会做错事吗？会，简历里至少留一句加指针，细则仍可放 README。**删除测试**——删了会立刻坏吗？会坏，进简历。

推论两条。同一事实只写一处：简历写「有这条规矩、违反的后果、去哪看」，标准全文放 README 或更下游；若两处内容几乎相同，通常是一方放错了——README 写了「每次必知」，或者简历抄了百科。过期的代价也不一样：简历过期会直接导致错误动作，README 过期只是让人误解。所以简历宁短勿滥，README 宁可写全。

## 何时使用

加内容之前先量，越线先精简；要装关口、要拆分、要把策略搬到别处（§七）时也用。

## 一、核心思想（比脚本更重要）

1. 门禁是一个必被执行的关口。skill 无执行保证（框架没加载、没被选中、人可绕过），不能充当门禁；关口的选法见 §四。
2. 判据用 token 不用字节（字节对中文失真约 3 倍）。体积只是可强制的代理，目标是信息不重复、可导航；越线是信号，不是结论。
3. 上限的目的不是少写，是逼出指针化下沉：靠信息搬家而非删关键约束。搬之前先审接收方：目标须存在、可用、且尚未持有该事实，绝不搬进失效、超限或重复的容器。
4. 阈值是策略，只有一处。权威值只写在度量实现里，任何地方不抄第二份数字。
5. 量将要生效的版本：有版本控制就量暂存版，没有就量工作区。前提缺失必须显式响应，不静默换个对象来量。
6. 缺依赖要响，不能静默；哑门禁比没门禁更危险（清单见 §四.1）。
7. **长度不是目标函数，把故事讲清楚才是。** 入口文档要让第一次翻开它的 Agent 说清三件事：这是什么地方、为什么有这些规矩、细节去哪找。这三件事本身就是内容，不是可以指出去的东西。精简要砍的是重复、背景、可派生的事实，不能砍因果与最短路径；一张每行都写着「→ 见某文件」的卡什么也没讲——读者得先跳出去，才知道为什么要跳。页数陡增是信号，页数变小不是成绩。

## 二、度量与判据

度量器只读、永不阻断；判据给退出码，供关口 fail-closed 调用。精确用法以脚本自述为准，本文件不复述参数。

| 指标 | 阈值语义 | 处置 |
|---|---|---|
| token 近似 | 过提醒线 | 提醒 |
| token 近似 | 过上限 | 拒绝，先精简 |
| gzip 体积 | 过冗余线 | 告警，查重复或灌水 |

数值与适用范围以 --print-policy 及度量实现自述为准，勿抄；别在任何文档里记当前数值（漂移事实），要现状现场量。

### 人类刻度（判决依据）

人感觉不到 token 与字节，感觉到的是页面：度量并列给出实排页数，判据本身仍只用 token。实排含短行与行尾留白，与算术值实测可差近一倍，**差值即排版开销**（格式堆砌的量）。换算绑定写死的排版标准。渲染器是外部依赖，不进判据、永不阻断；但缺依赖时要显式说明「这次没看到页面」——那等于判决没有依据（§〇）。

## 三、超限了怎么办

先定去留，再动手：

| 判定 | 何时适用 | 动作 |
|---|---|---|
| Keep 留 | 几乎所有任务都需要，稳定，无法派生 | 留在入口 |
| Point 指 | 部分任务才需要，有明确归属 | 下沉加指针（下方 2） |
| Derive 派 | 可从代码、配置、探针派生 | 删静态副本（下方 1） |
| Delete 删 | 历史背景，已失效，无决策价值 | 删除或归档（下方 3） |

0. 先审接收方（§一.3）：目标可用吗？该事实已在别处有源吗？
1. 删可由代码或探针派生的事实（计数、比例、当前值），改成以探针为准。
2. 指针化下沉：细节、背景、踩坑史移到下游，原地只留一行指针加稳定短名。
3. 归档历史：过期计划、被取代方案移到归档区。
4. 职责切割：不同读者或用途分开，同一内容只许出现在一处。
5. 拆分：按内在关系切分，入口路径稳定，引用按名不按号。必须降低默认上下文成本——Agent 仍需同时读全部碎片则不算数。
6. 保因果（§一.7）：搬走的是细节与背景；「为什么有这条规矩」和「最短怎么用」留在入口。判一条要不要留，问一句「读者不跳出去，能不能明白它」，不能就把理由一起留下。

判据按 token 量（字节只是代理），但别把数字当目标：合法的动作只有上面六种，且必须满足「信息搬家，约束不删；阈值变更需批准；关口必过；搬迁必治（§一.3）」。长度变短从来不是一次精简合格的证据，删了必要的话反而更糟。

## 四、把关卡装成必被执行的关口

机制层三角色：度量（只读）、判据（退出码）、安装器（幂等落地）。必须做到：

1. fail-closed：守卫缺失、解释器不可用、退出码意外，一律拦截并报错。
2. 薄壳加幂等：关口只在自己标记块里调用守卫，重跑不叠块；逻辑全在守卫里，多仓共用。
3. 量将生效版本（语义以判据脚本自述为准）：未纳入提交的显式跳过、未改动的存量豁免、前提缺失拒绝。
4. 装完实测拦截：越线被拦、合规能过、未改动能过，没实测不算装好。
5. 守卫本体随目标入库：只依赖技能目录会让 clone 的人静默失效。

选关口按「一定跑到」排序：有版本控制选提交点，其次流水线，再次启动入口或任意自动化；都没有就退化为入口提示，不假装已装。是否已装：跑校验，不背记忆。

## 五、给 AI agent 的行为规则

1. 改入口文档前后各量一次，越线先精简再提交。
2. 新增段落先估 token，估不准就量。格式符号同样占 token：满屏加粗、装饰符号、反复强调，全是重点等于没有重点；先去味，再谈内容精简。
3. 提交前量将生效版本，别把随手看到的数当提交的数。
4. 阈值、判据、算法一律引用权威源，不生成第三份数字。
5. 精简或拆分后验指针可达、验无第二事实源、按名改引用、重建下游检索索引；并报账：搬走什么、搬去哪、入口现在如何找到它。
6. 交付前跑终审（§六），此时才读 references/final-audit.md。
7. 别把「变短」当成交付证据。精简后通读一遍，确认读者仍能说出这是什么地方、为什么有这些规矩、细节去哪找（§一.7）；不能，就是砍过头了。
8. 判决看页面（§〇）：跑一次渲染，像读者那样通读实排结果；渲染器不可用时明说「这次没看到页面」，别只读一个 token 数字就宣布合格。

## 六、交付前终审（渐进式披露反例）

反例不进生成阶段的上下文，只在终审时读 references/final-audit.md。
终审：再量一次（§二），清单逐条答是或否；有否就返工再审，全是才交付。

## 七、可移植性

可移植单元是本目录（SKILL.md 加 scripts/）。硬约束：纯标准库、不联网、度量与判据不写文件、不依赖版本控制（它只是取将生效版本的增强）。

| 环境 | 怎么用 |
|---|---|
| 支持 skills | 放进 skills 目录，读 SKILL.md |
| 不支持 skills | SKILL.md 正文进系统提示词；工具直接跑 |
| 有版本控制 | 守卫装到提交点 |
| 只有流水线或启动入口 | 在其中 fail-closed 调判据 |

## 八、权威来源与自身一致性

- 阈值与算法唯一事实源：度量实现（--print-policy）。
- 本技能自身也守这些不变式：无第二事实源、无漂移引用、描述与随附物一致（提到的产物必须真随附，否则不提）。

## 九、文风（正面标准）

「愿意看」这一条（§〇）落在这里：密度治理回答「多不多」，文风回答「读不读得下去」。判据不是数标点，是「读起来像不像人写的」。四条可执行的方向：

1. 直陈。陈述事实，删掉铺垫、软化与拐杖词，比如「值得注意的是」「总的来说」「在一定程度上」。
2. 句子先于条目。条目只留给真正并列、需要扫读的内容。把解释塞进条目、拿「粗体标题加冒号」起头的面条列表，是最重的机器味。
3. 节奏要变。长短句交错，别让连续三句一个长度。列举时两项常常比三项自然，三段式是典型机器手感。
4. 具体胜于抽象。能写清谁、在哪、多少，就别写「相关」「多方面」「显著」；读起来像口号的句子，重写。

这套方向的完整版是「去 AI 味」的通行做法：识别填充词、公式化结构与虚张声势，剩下的是具体和节奏。
